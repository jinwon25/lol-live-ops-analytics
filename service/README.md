# 웹서비스 실행·확장 안내

현재 구성은 FastAPI + HTML/CSS/JavaScript다. API 키·원본 DB 없이 기존 기록과 참고 분석을 조회한다. 공식 전적 가져오기를 사용하려면 서버 키가 필요하다.

프로젝트 루트에서:

```powershell
python -m pip install -r service/requirements.txt
python -m uvicorn service.main:app --reload --host 127.0.0.1 --port 8001
```

브라우저: http://127.0.0.1:8001 · API 스키마: http://127.0.0.1:8001/docs

다른 서비스와 충돌하지 않도록 이 프로젝트는 8001 포트를 사용한다. 기존 기록은 호스트·포트별로 구분되므로 주소를 변경할 때는 이전 주소에서 백업한 뒤 새 주소에서 복원한다.

## 구성

| `data/catalogue.json` | 공식 한국어 챔피언 정적 자료의 버전 고정 사본 |
| `../web/` | 세 개 주 메뉴·자동 리포트·개인 기록·조건별 비교 |

## 개인 복기 사용

기본 흐름은 **내 전적·리포트 → Riot ID 조회 → 경기별 자동 리포트 → 선택 보관**이다. 수치 입력 없이 6개 지표·사실·질문을 제공한다. 보관함에서 다시 열거나 삭제한다. 자동 리포트는 최대 50개이며 현재 수동 복기용 JSON 백업에 포함되지 않는다. [구조·자동 리포트](../docs/12_structure_and_auto_reports.md)

직접 입력 복기 화면과 수치 수정으로 이동하는 버튼은 제거했다. 기존 복기 기록은 검색·수정·상태 관리·백업·복원할 수 있다. 새 경기는 전적 조회 후 리포트로 보관한다. 호환용 `/api/review`와 기존 저장소는 유지하지만 현재 화면에서 새 수동 기록을 만들지 않는다.

개인 경기·행동 기록은 이 브라우저의 localStorage에 최대 500개, 기존 자유 노트는 별도 최근 10개를 보관한다. 기존 버전의 경기 기록은 같은 저장 키로 읽으며 별도 초기화하지 않는다. 같은 조건·일시는 갱신한다. 한도를 넘으면 새 저장을 거부하며 기존 경기를 자동 삭제하지 않는다. 개인 비교는 지역·큐·게임 버전·티어·챔피언·포지션이 같은 6경기부터 최근 3개/직전 3개의 평균과 유효한 분모를 보여준다. 6경기는 표시 기준이며 통계적 유의성이나 실력 향상을 보장하지 않는다.

복기 장면·행동은 서버로 보내지 않는다. 요약을 위해 입력한 수치는 로컬 서버가 처리하되 디스크에 저장하지 않는다. 공유 PC에서는 경기별 삭제·자유 노트 삭제를 사용하거나 해당 사이트의 브라우저 데이터를 지운다. 브라우저 데이터 삭제 전에 경기 백업을 내보낸다.

### 기록 보관·재사용 — 2026-10-05

인사이트 보드에서 챔피언·경기 조건·복기 초점·장면·다음 행동·돌아본 내용을 검색한다. 목록은 최근 경기부터 20개씩 표시하며 첫 화면 밖의 기록도 검색한다. 각 경기의 `복기 기록 수정`으로 초점·확인한 사실·행동을 수정하거나 취소할 수 있다. 저장된 경기 조건·수치를 다시 입력하지 않아도 된다.

행동은 `시도 전 / 시도함 / 돌아봄`으로 직접 표시하고 시도 후 메모를 남길 수 있다. 상태별 필터와 보드의 수행 기록 수는 본인의 체크 기록이며 행동 효과·실력 향상의 판정이 아니다. 같은 경기의 수치를 다시 요약해 저장할 때 같은 행동의 수행 기록은 유지하며, 행동을 새로 바꾸면 `시도 전`으로 시작한다.

삭제 직후 `방금 삭제한 경기 되돌리기`로 한 경기를 복원할 수 있다. 새로고침이나 다음 삭제 이후에는 이전 삭제를 되돌릴 수 없으므로 장기 보관에는 백업을 사용한다. 다른 탭에서 이미 바꾼 경기의 오래된 수정 화면으로 저장하면 덮어쓰지 않고 최신 기록 확인을 안내한다. 이 보호는 일반적인 순차 편집에 대한 검사이며 여러 탭의 완전히 동시 쓰기를 트랜잭션으로 처리하는 구현은 아니다.

직접 입력 제거 이후 초안의 새 자동 저장·이어쓰기 UI는 제공하지 않는다. 과거 초안은 브라우저에서 자동 삭제하거나 덮어쓰지 않는다. 기존 저장 키와 호환 모듈은 보존했다.

`경기 기록 백업·복원`에서 JSON 파일을 내려받고, 같은 형식의 파일을 선택해 미리보기를 확인한 뒤 기록을 합친다. 서버에 파일을 업로드하지 않는다. 백업은 현재 보관한 최대 500개 경기의 조건·요약 수치·초점·장면·행동·수행 상태·시도 후 메모를 포함하며 자유 노트와 입력 중 초안은 포함하지 않는다. 장면·행동에는 개인 내용이 있을 수 있으므로 파일은 본인이 보관한다.

복원은 기존 기록을 유지하고 없는 경기를 추가한다. 같은 조건·일시는 현재 브라우저의 기록을 우선하며 추가·중복·복원 후 경기 수를 적용 전에 표시한다. 2MB 초과, 다른 형식·버전, 잘못된 경기·합성 예제·파일 내부 중복·병합 후 500개 초과는 전체 복원을 거부한다. 기존 저장소가 손상됐거나 저장이 실패하면 덮어쓰지 않는다. 브라우저 데이터 삭제·호스트/포트 변경 전에 백업하고 새 주소에서 복원한다. 이미 과거 버전의 50개 제한으로 제거된 경기는 복구하지 않는다. 자유 노트 백업과 더 큰 보관함은 후속 범위다.

선택적으로 Git에서 제외된 `.local/companion.json`에 `region`, `queue`, `tier`, `division`, `role`, `champions` 기본값을 둔다. 챔피언은 공식 ID 1–3개를 사용한다. 이는 현재의 입력 기본값이며 과거 경기 당시 조건을 확인하는 일을 대신하지 않는다. Riot ID·키·전적은 이 파일에 넣지 않는다.

## 개인 분석 리포트와 이미지 — 2026-10-05

저장한 경기가 있으면 인사이트 보드 첫 화면에 개인 분석 리포트를 표시한다. 비교 조건을 선택한 뒤 분당 골드·피해량·시야 점수·킬 관여율의 최근 최대 10경기 추이를 확인한다. 평균 차이와 그 지표에 연결된 복기 질문을 함께 표시하며, 상세 평균 표와 경기별 수치는 펼쳐서 읽는다. 6경기 미만은 평균 비교를 보류하고 계산 불가 값은 0으로 대체하지 않는다. 질문은 공개된 고정 질문 템플릿이며 자동 약점 진단이 아니다.

`다음 경기 과제`는 기존 기록의 최신 미완료 과제 3개다. `행동 노트에 가져오기`는 이전 행동을 자유 노트 입력에 가져온다. 200자를 넘는 내용은 자동으로 잘라 저장하지 않고 기존 기록을 확인하도록 안내한다. 분석 질문도 행동 노트로 가져올 수 있다. `기록 열어 돌아보기`로 원래 기록을 열어 시도 여부와 메모를 수정한다.

공식 초상 173개를 챔피언 탐색·경기 기록·가져온 경기·복기 결과에 표시한다. 이미지는 `web/images/`에 보관하므로 실행 시 외부 CDN 호출이 필요하지 않다. 아이콘 출처·버전·파일 해시는 `web/images/manifest.json`, Tabler MIT 고지는 `web/images/icons/LICENSE`에 있다. [화면 개선·개인 분석 구현 기록](../docs/10_personal_analysis_ui.md)

## 공식 전적 연결

[Riot Developer Portal](https://developer.riotgames.com/)에서 본인용 키를 발급·신청한다. 개발 키는 24시간마다 만료되며 공개 운영용 키와 다르다. [키 종류·연동 방식 검토](../docs/08_riot_integration.md)

지속적인 개인 연구·본인 전적 분석은 제품을 등록해 개인 키를 신청할 수 있다. 24시간 비활성화는 개발 키에 명시된 조건이며 개인 키는 상세 사용 목적과 Riot 검토가 필요하다. 공개 이용자 대상 운영에는 프로덕션 키가 필요하다. 개인 키 신청용 설명 예시는 위 연동 문서에 정리했다.

프로젝트 루트에서 최초 설정:

```powershell
if (-not (Test-Path -LiteralPath service/.env)) {
    Copy-Item -LiteralPath service/.env.example -Destination service/.env
}
```

로컬 편집기로 `service/.env`의 `RIOT_API_KEY=`에 실제 키를 입력한다. 파일은 Git에서 제외한다. 키를 채팅·브라우저 폼·README에 입력하지 않는다. 환경 변수가 이미 설정되어 있다면 파일 없이 기본 실행 명령을 사용해도 된다.

```powershell
python -m uvicorn service.main:app --reload --host 127.0.0.1 --port 8001 --env-file service/.env
```

경기 복기 화면에서 Riot ID 게임 이름·태그를 입력한다. KR 솔로듀오 최근 5/10개를 선택해 조회하며 연결 경로는 로컬에서만 허용한다. 현재 랭크는 별도 표시하고 경기 당시 티어는 자동 적용하지 않는다. 경기 선택 후 핵심 요약·팀 비교·시간대별 흐름을 확인한다. 흐름은 별도 공식 타임라인을 필요할 때 불러온다. 입력한 ID는 로컬 서버와 Riot에 전달되지만 이 구현은 ID·PUUID·원본 전적을 디스크에 저장하지 않는다.

키 설정 여부와 유효성은 다르다. 401/403은 키·권한·만료를 확인하고, 429는 응답의 대기 안내를 따른다. 404는 ID·태그를 확인한다. 누락·짧은 경기·조기 종료·미지원 포지션은 제외한다. API 키·응답·원본 전적을 공개 로그에 추가하지 않는다.

## 공식 자료 갱신

```powershell
python scripts/sync_catalogue.py
# 필요하면 공식 목록에 존재하는 버전을 고정
python scripts/sync_catalogue.py --version 16.19.1
```

자료에 버전·확인 시각·공식 URL·정규화된 원본 JSON 해시를 남긴다. 서비스 실행 중 갱신했다면 서버를 재시작한다. 공식 패치 노트 링크·게시일은 검토 후 `main.py`의 별도 기록도 갱신한다. 정적 자료 갱신으로 승률이나 과거 분석 CSV가 갱신되지는 않는다.

## 검증

```powershell
python -m unittest discover -s tests -v
node --test tests/test_journal.cjs tests/test_analysis.cjs tests/test_reports.cjs
```

현재 CI는 원본 데이터·실제 키 없이 가능한 서비스 API와 기록 병합 경계 검증이다. JavaScript 검증은 Node.js 18 이상을 사용하고 CI는 20으로 고정한다. 원본을 이용한 전체 SQL·군집 분석과 실시간 API 운영을 대신하지 않는다.

브라우저 흐름 검증은 CI에 포함하며 로컬에서도 실행할 수 있다. 임시 서버는 검증 후 종료된다.

```powershell
python -m pip install playwright
python -m playwright install chromium
python scripts/check_service_ui.py
```

실행 중인 로컬 서버의 필수 파일·분석 연결과 선택 기능의 준비 상태를 점검한다. 계정 조회나 모델 추론은 실행하지 않으며 설정 확인과 실제 연결·품질 검증을 구분한다.

```powershell
python scripts/check_service_readiness.py
```

## 후속 개발 경계

기존 `api/`는 SQLite 적재 PoC이고 `service/riot.py`는 원본을 저장하지 않는 선택 조회다. 단일 로컬 서버의 메모리 캐시·제한을 여러 이용자 운영에 그대로 사용하지 않는다. 로컬 모델은 역할·6개 지표만 받고 계정·장면·원본 전적을 받지 않는다. CPU 실행을 요청할 때만 사용하며 실패해도 기본 리포트는 유지한다. [확장 모델 비교·재현 명령](../docs/14_model_selection_audit.md) · [초기 LoRA 실험](../docs/13_local_llm_research.md) · [상용 UI 참고와 화면 검증](../docs/15_commercial_ui_refinement.md) · [공개 데이터 조사](../docs/11_public_data_research.md). 공개 서버 배포 전에 제품 등록·승인과 운영용 키 범위를 확인한다. ## 현재 메타 표본 수집과 챔피언 도감

공식 API에서 수집한 KR 16.19 제한 표본 282경기·2,820참여 행을 연결했다. 실버 II 계정에서 출발했으며 모든 참가자의 경기 당시 티어를 확인한 통계는 아니다. 30회 미만의 역할별 승률은 표시하지 않는다. 챔피언 도감의 기술 설명은 공식 Data Dragon에서 필요할 때 읽으며 CDN 연결 실패 시 안내한다.

```powershell
python scripts/collect_riot_meta.py --seeds 40 --per-seed 20 --pages 3 --matches 500 --max-calls 650
```

완료 경기 상세·타임라인은 24시간 메모리 캐시, 계정은 10분, 랭크는 2분, 목록은 60초 캐시다. 429의 Retry-After와 앱·메서드 응답 헤더를 반영하며 수집기는 중복 경기 해시·비식별 체크포인트·원자적 저장·요청 예산을 사용한다. 자동 주기 수집은 설정하지 않았다. 여러 프로세스의 대규모 운영에는 공유 예산이 필요하다. [표본 정의·구현·검증·공식 참고자료](../docs/17_match_explorer_and_riot_collection.md)
