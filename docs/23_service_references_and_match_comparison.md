# 관련 서비스 참고와 보관함 경기 비교 — 2026-11-15

보관한 자동 리포트를 다시 찾고 두 경기의 수치를 함께 보는 흐름을 개선했다. 기존 수동 복기 분석과 별도로, 이미 저장한 최대 50개 리포트에서 동작한다. 새 계정 식별자나 서버 저장 구조를 추가하지 않는다.

공개 공식 소개와 도움말을 확인한 범위이며 유료 기능·로그인 내부 화면을 직접 비교 평가한 것은 아니다. 경쟁사 점수·추천 모델·사용자 통계를 가져오거나 화면을 복제하지 않았다. 스타 수나 상용 서비스의 인기도를 기능 효과의 검증으로 해석하지 않는다.

Ponytail의 기존 코드 재사용 원칙에 따라 `MatchReports`에 순수 검색·비교 함수를 추가했다. Impeccable의 Operate·craft-floor 지침과 기존 화면 자료를 참고해 블랙·골드 테마, 기본 선택 상자, 명시적 상태·레이블, 빈 결과의 복구 동작을 유지했다. Impeccable 문맥 로더는 실행하지 못해 기존 코드와 문서를 직접 확인했다.

## 사용할 수 있는 흐름

1. **보관함 → 보관한 경기 리포트**에서 챔피언·패치를 검색하고 포지션과 승리·패배·결과 미확인으로 좁힌다. `원딜`, `바텀`, `서폿` 등 한국어 포지션 검색도 지원한다.
2. 각 경기의 **비교 선택**을 눌러 최대 두 개를 고른다. 목록에 패치·경기 길이·결과·일시를 함께 표시한다.
3. 필터를 바꿔도 선택은 유지되며, 현재 필터 밖에 선택된 경기 수를 안내한다. 위쪽 선택 목록에서 개별 해제하거나 **비교 선택 초기화**로 모두 해제한다.
4. 같은 챔피언·포지션·패치이면 이전/이후 경기 순으로 6개 지표와 차이를 표시한다. 다른 조건이면 선택 목록과 사유를 보여주고 차이 계산은 보류한다.

분당 골드·챔피언 피해·시야·CS, 킬 관여율·팀 내 피해 비중을 비교한다. 비율의 차이는 `%p`이며 계산 불가 값은 `—`로 남긴다. 지표 증가를 성과 향상으로 색칠하거나 점수화하지 않는다. 경기 시간과 결과를 함께 제시하고, 동일 플레이어인지 확인할 수 없으며 상대·조합·당시 티어 차이가 있을 수 있음을 안내한다. 단 두 경기의 수치는 실력 변화나 승패 원인을 입증하지 않는다.

비교 선택은 현재 페이지 메모리에만 존재하고 새로고침하면 해제된다. 기존 저장 키·백업 버전·50개 한도는 유지한다. 다른 탭에서 선택한 경기를 삭제하면 기존 `storage` 처리로 선택을 정리한다. 손상된 보관함에서는 오래된 비교를 제거하고 원문을 덮어쓰지 않는다.

## 검증 결과

- JavaScript 전체 **34개 통과**. 새 4개 검사는 검색·필터 결합, 원문 보존, 일시순 정렬·6개 지표 차이, 누락과 0의 구분, 조건 불일치·중복·손상 거부를 검증한다.
- Python 정적 파일 검사 **2개 통과**, 변경 JavaScript 구문·브라우저 검사 Python 구문·HTML 중복 ID와 컨트롤 위치를 확인했다. 백엔드는 이번에 변경하지 않았다.
- 실제 Chrome에서 별도 로컬 주소의 빈 보관함과 필터·비교 안내가 렌더링되는 것을 확인했다. 파일 선택창 조작이 완료되지 않아 합성 경기 복원 이후의 비교 표·모바일 화면은 직접 검증하지 못했다. 검증용 탭은 닫았으며 기존 개인 기록 주소는 사용하지 않았다.
- 기존 CI 브라우저 검사에 필터 밖 선택 유지, 두 경기 제한, 조건 불일치, 누락 표시, 키보드 초점, 다섯 화면 너비와 다른 탭의 선택 경기 삭제 검사를 추가했다. 자동 브라우저 연결을 사용할 수 없어 실행 성공을 주장하지 않는다.

합성 백업은 무작위 실제 계정 조회 없이 만들었고 개인 식별자를 포함하지 않는다. 실제 Riot 요청·모델 추론·외부 배포는 수행하지 않았다.

## 다음 작업

우선 실행 가능한 환경에서 추가한 브라우저 회귀 검사를 완료한다. 이후 보관한 경기에서 확인한 장면과 행동 노트를 직접 연결하는 흐름을 검토할 수 있다. 장기 추세와 동티어 비교는 계정 구분·표본 출처·조건 정의를 먼저 마련해야 하며, 현재 무식별 리포트들을 자동으로 같은 사람의 경기로 묶지 않는다. 최신 패치 통계 갱신과 AI 품질 평가는 [이전 우선순위](22_shared_budget_followup.md)를 따른다.
