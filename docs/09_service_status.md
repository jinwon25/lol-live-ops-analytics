# 웹서비스 현황 점검과 기록 보관·재사용 개선

확인일: 2026-10-05. 사용자가 선택한 후속 우선순위는 **복기 기록의 보관·재사용 개선**이다. 기존 로컬 서비스의 코드·문서·테스트·브라우저 흐름을 확인하고, 기록을 다시 찾고 이어서 다듬는 기능을 확장했다. [현재 사용법](../service/README.md) · [전체 기획](06_companion_plan.md)

같은 날 추가 요청으로 공식 이미지·UI 정리와 개인 분석 리포트·이전 과제 재사용도 구현했다. 아래는 먼저 완료한 보관 작업의 기록이며, 최신 화면과 추가 검증은 [화면·개인 분석 개선](10_personal_analysis_ui.md)에 정리했다.

## 내일 먼저 확인할 것

1. 아래 실행 명령으로 서비스를 열고 인사이트 보드의 검색·행동 상태 필터를 확인한다.
2. 저장한 경기의 `복기 기록 수정`에서 장면·행동·수행 상태·시도 후 메모를 수정한다. 경기 조건과 수치는 유지한다.
3. `경기 기록 백업·복원`을 열어 JSON을 내려받고, 파일을 다시 선택해 병합 미리보기를 확인한다. 같은 조건·일시는 현재 기록을 우선한다.
4. 경기 복기에서 수치를 입력하다 새로고침하고 `남겨둔 경기 초안 이어쓰기`를 확인한다. 초안은 요약을 다시 확인한 뒤 경기로 저장한다.

```powershell
cd D:\프로젝트\game
python -m uvicorn service.main:app --reload --host 127.0.0.1 --port 8001
```

브라우저: http://127.0.0.1:8001 . 이번 점검에서 8000 포트는 다른 프로젝트가 사용 중이었으므로 해당 프로세스를 종료하지 않았다. Riot 연결이 필요하면 기존 실행 안내에 따라 서버 환경 변수 또는 `--env-file service/.env`를 사용한다. 키 파일을 새로 만들거나 기존 키를 바꾸지 않았다. 주소의 호스트·포트가 달라지면 브라우저 저장 공간도 달라지므로 이전 주소의 기록은 JSON으로 내보내 새 주소에서 복원한다.

검토용 로컬 서버를 8001 포트에 실행해 두고 API 버전 0.3.0·키 설정 여부를 확인했다. 기존 `service/.env`를 사용하고 실제 계정 조회는 하지 않았다. 실행 정보는 Git에서 제외된 `.local/game-preview.json`에 보관했다. 컴퓨터 재시작 등으로 서버가 종료되면 위 명령으로 다시 시작한다. 실제 키 유효성은 전적 조회 시 확인한다.

## 점검 당시 상태

기준 커밋은 `ee01861`이며 작업 시작 당시 미커밋 변경은 없었다. Python 3.11.2, Node.js 18.20.5에서 확인했다. FastAPI와 순수 HTML/CSS/JavaScript로 구성되어 프런트엔드 빌드·npm 설치 과정은 없다.

| 영역 | 확인한 구현 | 남은 범위 |
|---|---|---|
| 개인 복기 | 수동 입력·4가지 초점·GPM/DPM/시야/분/KP 요약·조건별 저장 | 경기 당시 티어와 장면은 사용자 확인 필요 |
| 내 경기 비교 | 지역·큐·게임 버전·티어·챔피언·포지션이 같은 최근 3/직전 3경기 평균과 유효 분모 | 경기 길이·상대·승패·게임 흐름 통제, 효과 검증 |
| Riot 연결 | KR 솔로듀오 최근 경기·현재 랭크·메모리 캐시·호출 제한·로컬 경계 | 타임라인, 다중 서버 운영, 인증·승인 범위 |
| 챔피언 탐색 | 공식 정적 자료 16.19.1과 과거 역할·패치 집계를 구별해 표시 | 최신 KR 승률·빌드 추천 |
| 분석 도우미 | 등록된 집계·키워드·응답 템플릿·출처·자료 부족 안내 | LLM 추론, 개인 기록을 읽는 도구 |

| 검증 | 서비스 API, 모의 Riot 응답, Playwright 주요 화면·모바일 | 실제 키 재조회, 공개 운영·자동 브라우저 CI |

원본 분석 경로 `src/`, 별도 수집 PoC `api/`, 개인 복기 연결 `service/riot.py`는 서로 다른 실행 경로다. 원본 데이터·DB를 재생성하거나 덮어쓰지 않았다. 2026-10-04 실제 Riot 조회 성공 기록은 이전 검증이며 이번 작업의 실시간 재검증으로 표시하지 않는다.

로컬에 두 원본 파일과 분석 DB·API PoC DB가 존재하는 것도 확인했다. 존재 여부·파일 목록만 확인했으며 원본 행을 읽거나 모델을 재학습하지 않았다. 서비스 API 버전은 이번 기록 개선에 맞춰 0.3.0으로 올렸다.

## 이번에 추가한 기록 흐름

| 기능 | 동작과 보존 기준 |
|---|---|
| 장기 기록 | 기존 저장 키를 그대로 사용해 최대 500개 보관. 한도를 넘으면 새 저장·전체 복원을 거부하고 기존 경기를 자동 삭제하지 않음 |
| 검색·목록 | 챔피언 한국어/공식 ID·조건·복기 초점·장면·행동·시도 후 메모 검색. 최근부터 20개씩 표시하고 전체 기록에서 검색 |
| 복기 수정 | 저장한 경기의 초점·장면·행동을 수정·취소. 경기 조건·요약 수치 유지 |
| 수행 기록 | `시도 전 / 시도함 / 돌아봄`과 시도 후 메모. 상태 필터와 본인 체크 수 제공 |
| 초안 이어쓰기 | 입력 중 수치·장면·행동을 0.5초 뒤 브라우저에 보관. 새로고침 후 명시적으로 이어쓰기. 기존 초안과 합성 여부를 보존 |
| JSON 백업 | 조건·요약 수치·장면·행동·초점·수행 상태·시도 후 메모만 내보냄. 추가 식별자·알 수 없는 필드는 출력에서 제외 |
| 복원 미리보기 | 파일 전체 검증 후 추가·중복·복원 후 수 표시. 현재 기록을 우선해 병합. 파일은 서버로 전송하지 않음 |
| 삭제 취소 | 현재 화면의 마지막 삭제 한 경기를 되돌림. 동일 경기가 새로 작성됐다면 덮어쓰지 않음 |
| 다른 탭 보호 | 다른 탭의 변경을 목록에 반영. 오래된 경기 편집 화면은 변경 감지 후 저장 거부. 다른 탭의 초안 변경 시 자동 보관 중지 |

기존 기록에 새 수행 필드가 없으면 `시도 전`으로 해석한다. 같은 경기·같은 행동을 다시 요약해 저장해도 수행 기록을 보존하며, 행동을 새로 바꾸면 수행 상태를 새로 시작한다. 수행 체크는 자기 보고이며 행동 효과·승률 개선의 검증 결과가 아니다.

백업은 버전 1 JSON, 최대 2MB·500개 경기다. 잘못된 형식·버전·미래 경기·잘못된 수치·합성 예제·파일 내부 중복을 전체 거부한다. 손상된 기존 저장소와 저장 용량 오류도 기존 데이터를 덮어쓰지 않는다. 자유 노트 10개와 입력 중 초안은 경기 백업에 포함하지 않는다.

| 문제 | 수정·확인 |
|---|---|

| 기존 50개 제한의 자동 삭제 | 500개 한도와 초과 시 저장 거부로 변경. 과거에 이미 제거된 기록은 복구하지 않음 |

## 검증 결과와 실제 범위

```powershell
python -m unittest discover -s tests -v
node --test tests/test_journal.cjs
python scripts/check_service_ui.py
```

- Python API 테스트 19개: 근거 범위·입력 경계·KP 분모·Riot 라우팅/캐시/429·비정상 응답·개인 식별자 제외 확인.
- JavaScript 테스트 13개: JSON 왕복·중복 병합·손상/용량 실패 보존·500개 한도·최대 길이 한국어 백업·수행 필드·충돌/삭제 취소·초안 입력 경계 확인.
- Playwright: 네 화면, 예제/초안의 합성 여부, 기록 저장·삭제·되돌리기, 검색·수정·취소, 수행 상태·다른 탭 충돌, 다운로드·복원 미리보기, 초/밀리초 왕복, 20개씩 표시·오래된 경기 검색, 390px 모바일에서 가로 넘침과 콘솔 오류 확인.
- CI에는 실제 키·원본 없이 실행하는 Python/JavaScript 검사를 등록했다. Playwright는 로컬에서 실행했고 원격 CI 결과는 이번 작업에서 확인하지 않았다.
- 변경 문서 6개의 Markdown을 외부 전송 없이 로컬 렌더링해 표 열 수·취소선·코드 블록·상대 파일 링크를 확인했다. 데스크톱·390px 모바일의 기록 수정 화면도 합성 데이터로 촬영해 입력·버튼 배치를 확인했다.

검증용 브라우저는 별도 Chromium 컨텍스트와 임시 포트를 사용한다. 개인 기본값을 모의 응답으로 가리고 합성 기록만 넣었다. 평소 브라우저의 저장 기록을 조작하거나 실제 Riot 계정을 조회하지 않았다.

| 1 | 본인 사용성 확인 | 초안 이어쓰기·장면 검색·수정·백업 복원으로 실제 기록을 다시 찾을 수 있는지 확인 |
| 2 | 보관 확장 | 자유 노트/초안 백업, IndexedDB·트랜잭션·다중 탭 동시 쓰기 검토. 기존 기록 보존과 마이그레이션 실패 복구를 먼저 설계 |
| 3 | 복기 근거 확장 | 공식 타임라인의 실제 제공 필드를 감사하고 수동 장면과 대조. 시야 가시성·의도·스킬 적중을 자동 복원한다고 주장하지 않음 |
| 4 | 분석 도우미 연결 | 개인 기록 도구와 근거 스키마·평가 사례를 만든 뒤 선택적인 LLM 연결·비용 한도 결정 |
| 5 | 공개 운영 | 승인·운영 키·인증·데이터 수명·다중 서버 호출 제한을 확인한 뒤 운영 경로 분리 |

localStorage의 모든 탭 쓰기를 원자적인 트랜잭션으로 처리하지 않는다. 이번 충돌 검사는 순차 변경을 감지하며 같은 순간의 쓰기 경쟁은 IndexedDB 등 후속 설계가 필요하다. 초안은 한 개이며 다른 탭의 변경 안내 후 선택적으로 이어쓴다. 삭제 취소는 현재 화면의 마지막 삭제만 지원한다. 다른 기기 자동 동기화·계정별 저장·최신 승률 추천·자동 타임라인 진단·LLM 추론·코칭 효과 판정은 이번 구현에 포함하지 않는다.

로컬 변경과 검증을 완료했으며 커밋·푸시·외부 공개 배포는 이번 작업에서 수행하지 않았다.
