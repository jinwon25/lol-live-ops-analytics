# EUN·KR 솔로랭크 패치별 표본 점검

EUN과 KR의 솔로랭크를 같은 게임 버전에서 비교한다. 아래 결과는 2026년 11월 21일에 CSV·압축 원본·체크포인트를 대조한 6,489경기 기준이다. 이후 주간별 보강을 진행 중이다. 참가자를 따라 수집하므로 경기 당시 티어를 알 수 없고 동일 선수의 반복 참여가 생길 수 있다.

## 검증 표본과 주요 결과

양쪽 지역의 97개 주간마다 기존 후보 계정 한 개를 골라 목록 194건을 조회했다. 같은 계정·주간에서 최대 두 경기를 선택했고, 이미 조회한 경기 키는 제외했다.

| 지역 | 수집 전 | 상세 조회 | 검증 후 추가 | 누적 경기 |
| --- | ---: | ---: | ---: | ---: |
| EUN | 3,104 | 127 | 121 | 3,225 |
| KR | 3,131 | 137 | 133 | 3,264 |

상세 조회 264건 중 9건은 조기 항복이면서 경기 시간이 허용 범위를 벗어났다. 다른 1건은 실제 시작 시각이 요청한 주간보다 13분 46초 빨라 제외했다. 검증 후 6,489경기의 CSV·압축 원본·체크포인트를 대조했다. 기존 EUN 분석 DB의 8,358경기와 이번 누적 EUN 표본에는 같은 경기 키 19개가 있다.

양쪽에 30경기 이상 있는 46개 패치 중 35개에서 EUN 표본의 경기 시간 중앙값이 더 길었다. 패치별로 EUN 중앙값에서 KR 중앙값을 뺀 뒤 그 차이의 중앙값을 구하면 74초였다.

같은 패치·챔피언·포지션에 두 지역 모두 30건 이상 있는 조합은 15.24 패치 바텀 미스 포츈 하나였다. EUN은 38회 선택 중 23승으로 60.5%(Wilson 95% 구간 44.7–74.4%), KR은 35회 선택 중 23승으로 65.7%(49.2–79.2%)였다. 표본이 작고 경기 당시 티어를 맞출 수 없어 지역별 우위를 판단하기 어렵다. 집계 코드와 DuckDB SQL로 선택 건수·승수·경기 시간 차이를 각각 계산해 대조했다.

## 파일 검증과 재현

장시간 수집 목표는 2025년 1월 6일 00시부터 2026년 11월 16일 00시 직전까지의 97개 UTC 주간에 지역별 500경기씩, 총 97,000경기다. 로컬 환경에 Riot API 키를 설정하고 해당 지역의 실제 출발 경기 ID를 담은 비공개 파일을 준비한다. 아래는 KR 실행 예시다. EUN 수집은 지역과 출발 파일을 함께 바꾼다.

```powershell
python scripts/backfill_matches.py --region KR --seed-file .local/backfill_seeds_kr.txt --start 2025-01-06 --end 2026-11-16 --per-bucket 500 --delay 2.6 --until-complete
```

이 모드는 지역의 모든 주간이 목표에 닿으면 저장 파일과 체크포인트를 대조한 뒤 종료한다. 후보가 먼저 소진되면 부족한 경기 수를 출력한다. 일시적인 서버 오류는 재시도하며, 실행에 사용한 로컬 환경 파일의 키가 인증 거부되면 파일에서 새 키를 확인할 때까지 대기한다. PC 재시작 후에는 같은 명령으로 마지막 저장 상태에서 이어간다.

CSV에서 지역·경기별 참여자 번호 1–10과 경기 내 버전·시간·수집 구간의 일치를 검사했다. 이어서 압축 원본의 경기 키와 CSV 경기 키를 일대일로 대조했다. 첫 점검 시 CSV와 원본 양쪽에 저장됐으나 체크포인트 집계에 빠진 경기가 EUN 25건, KR 6건 있었다.

`game`에서 다음 명령을 실행하면 API 호출 없이 저장된 표본의 구간 수, 패치별 경기 수와 경기 시간 중앙값을 다시 확인할 수 있다.

```powershell
python scripts/backfill_matches.py --region EUN --audit-only
python scripts/backfill_matches.py --region KR --audit-only
```

다음 명령은 두 지역의 파일과 체크포인트를 함께 검증한 뒤, 같은 패치에서의 경기 시간 차이와 양쪽에 각각 30건 이상 있는 챔피언·포지션의 선택 건수, 승수, 승률, Wilson 95% 구간을 출력한다. 승률의 분모는 해당 지역·패치·챔피언·포지션의 선택 건수다. 연쇄 수집에서 반복된 선수를 보정하지 않은 참고 구간이다.

```powershell
python scripts/compare_backfill.py
```

수집기는 재시작 시 두 파일을 대조하고 저장된 경기 키와 구간별 건수를 복구한다. 파일 한쪽에만 있는 경기나 불완전한 참가자 행이 있으면 쓰기 전에 중단한다. 수집을 시작하지 않고 검증된 상태만 반영할 때는 같은 명령에 `--audit-only` 대신 `--repair-checkpoint`를 사용한다. 원본·참가자 행·체크포인트는 `.local/backfill/`에 보관한다.

## 분석용 파일로 내보내기

수집 결과는 로컬 CSV·압축 원본·체크포인트에 보관한다. 분석용 압축 PKL은 마지막 체크포인트에 반영된 참여 행을 읽어 별도로 생성한다.

```powershell
python scripts/export_backfill_pickle.py
```

출력은 `.local/exports/backfill_participants.pkl.gz`이다. `--when-complete`를 붙이면 양쪽 97주가 모두 주당 500경기를 채울 때까지 대기한다. 그 뒤 저장 파일을 대조하고 압축 PKL을 다시 읽어 일치할 때 기존 분석용 파일을 교체한다.

## 11월 21일 첫 번째 추가 수집

기존 표본이 적은 주간부터 지역별로 36개씩 경기 목록을 조회했다. 새 후보 98경기의 상세 응답에서 요청한 경기·지역·큐·주간·참가자의 일치를 확인했다. 조기 항복이면서 시간 범위도 벗어난 2경기와 포지션이 불완전한 1경기를 제외했다.

| 지역 | 이전 경기 | 검증 후 추가 | 배치 종료 시점 누적 |
| --- | ---: | ---: | ---: |
| EUN | 3,049 | 55 | 3,104 |
| KR | 3,091 | 40 | 3,131 |

배치 종료 후 원본과 CSV의 경기 키를 다시 대조했다. 누적 6,235경기의 체크포인트 차이는 두 지역 모두 0건이었다. 같은 패치·챔피언·포지션에 양쪽 모두 참여 기록이 30건 이상인 조합은 1개였다. 아래 경기 시간 비교는 11월 20일 표본을 기준으로 한다.

## 표본 범위

경기 시작 시각은 2025년 1월 6일–2026년 11월 15일 UTC다. 알려진 경기의 참가자를 따라 인접 주간의 경기를 수집했고, 주간 할당량이 덜 찬 구간부터 채웠다. 아래에서 패치는 Match-V5 게임 버전의 앞 두 자리다.

| 지역 | 고유 경기 | 참여 행 | 주간 구간당 경기 | 관측 패치 |
| --- | ---: | ---: | ---: | --- |
| EUN | 3,049 | 30,490 | 31–32 | 14.24, 15.1–15.24, 16.1–16.22 |
| KR | 3,091 | 30,910 | 31–33 | 14.24, 15.1–15.24, 16.1–16.22 |

## 같은 패치에서의 경기 시간

지역별로 한 경기를 한 번 세어 초 단위 경기 시간의 중앙값을 구했다. 두 지역 모두 30경기 이상인 패치에 같은 가중치를 주었을 때, **EUN 중앙값에서 KR 중앙값을 뺀 차이의 중앙값은 71초**였다. 아래는 가장 많은 경기를 확보한 패치, 가장 최근 패치, 비교 기준에서 제외한 패치다.

| 패치 | EUN 경기 | EUN 중앙값 | KR 경기 | KR 중앙값 |
| --- | ---: | ---: | ---: | ---: |
| 15.24 | 157 | 30.1분 | 158 | 28.3분 |
| 16.22 | 50 | 28.6분 | 55 | 28.7분 |
| 14.24 | 10 | 33.9분 | 8 | 26.8분 |

30경기는 이번 기술 통계에 사용한 표본 기준이다. 연쇄 수집으로 같은 선수가 여러 경기에 참여할 수 있고, 경기 당시 티어도 확인할 수 없다. 관측한 차이를 지역 전체의 플레이 성향이나 패치 효과로 일반화하기 어렵다.
