# 리포트 백업·복원과 로컬 서비스 보호 — 2026-11-15

전적 조회 뒤 보관한 자동 리포트를 다른 브라우저로 옮기거나 복구할 수 있도록 백업·미리보기·복원을 추가했다. 기존 블랙·골드 테마와 저장 키를 유지하며 외부 접근 경계와 Docker의 DB 저장 경로도 보완했다.

## 구현한 변경

| 영역 | 변경과 범위 |
| --- | --- |
| 자동 리포트 | JSON 백업·복원, 최대 50개·4MB 입력, 중복은 현재 내용 우선, 미리보기·취소 |
| 보관함 | 챔피언·영문 ID·포지션·패치 검색, 검색 결과 수, 검색 단축키, 마지막 삭제 취소, 버튼의 경기별 접근성 이름 |
| 자료 보존 | 복원 직전 현재 자료 재검사·재병합, 손상된 저장소 변경 거부, 초과·저장 실패 시 기존 자료 유지 |
| API 경계 | 동기화는 로컬·사설망의 같은 출처로 제한. 공개 IP·외부 Origin·공개 전달 주소 거부. 응답은 `no-store` |
| 기록 구분 | 개별 조회에 `client_id` 사용. 다른 클라이언트의 수정·삭제 거부와 DB 충돌 갱신 조건 적용 |
| 실행 | 루트에서 사용하는 설치 파일 경로 수정. Docker의 DB 디렉터리 권한·영구 볼륨·루프백 포트 적용 |
| CI | 자동 리포트 백업 UI 회귀 검사, Compose 설정 검사, 일반 사용자 DB 쓰기와 컨테이너 재생성 간 데이터 유지 검사 추가 |

리포트 백업은 `lol-insight-match-reports` 버전 1이다. 기존 `lol-insight-ranked-reviews` 수동 복기 백업과 다르며 서로 자동 변환하지 않는다. 행동 노트·초안은 포함하지 않는다. 백업은 계정 ID·PUUID·원본 참여자 목록을 제외하는 기존 필드 허용 목록을 사용한다.

삭제 취소는 현재 페이지의 마지막 삭제 한 개만 보관한다. 새로고침·다음 삭제 뒤에는 이전 삭제를 취소할 수 없다. 여러 탭이 정확히 동시에 쓰는 상황을 트랜잭션으로 처리하지 않으며, 장기 보존은 파일 백업으로 한다.

## 참고한 스킬과 적용 방식

검색 가능한 설치 경로에서는 Ponytail·Impeccable을 찾지 못해 원저자의 공개 파일을 읽었다. 출처와 지침을 확인한 것이며 해당 스킬의 효과를 독립적인 벤치마크로 입증했다는 뜻은 아니다. 전역 스킬이나 훅을 새로 설치하지 않았다.

- [Ponytail 원본 SKILL.md](https://github.com/DietrichGebert/ponytail/blob/main/skills/ponytail/SKILL.md): 기존 저장 구조와 검증기를 재사용하고 새 런타임 의존성 없이 구현했다.
- [Impeccable 원본 SKILL.md](https://github.com/pbakaus/impeccable/blob/main/.agents/skills/impeccable/SKILL.md), 확인 버전 4.9.1: Operate 기준과 harden·craft-floor 지침을 참고했다. 기존 시각 정체성을 유지하고 미리보기·취소·오류 복구·키보드 접근·작은 화면 배치를 다듬었다. 실행기가 없어 기존 코드·문서·저장된 화면을 직접 읽었다.
- 설치된 Sites의 로컬 프로젝트 검증 절차와 Computer Use를 적용해 실행 중인 보관함과 파일 복원 흐름을 확인했다.

## 검증 범위

Python·Node 검증은 실제 Riot 계정·키 요청이나 모델 추론 없이 수행한다. 추가 API 검사는 임시 SQLite DB, 화면 복원은 기존 8001 주소와 다른 임시 포트와 합성 리포트를 사용했다. 개인 원본 DB·키·기존 브라우저 기록을 마이그레이션하지 않았다.

Node는 백업 왕복·중복 보존·미리보기 뒤 변경·저장 실패·잘못된 형식·한도 초과·최대 길이 한국어 50개·삭제 취소를 검사한다. Python은 기존 API·분석 검사에 외부 접근 차단과 다른 클라이언트의 조회·수정·삭제·충돌 저장 거부를 추가했다.

이번 실행에서 Python 64개와 Node 25개가 모두 통과했다. 실행 중인 임시 서버의 준비 상태 점검은 필수 연결 실패 없이 `limited`였으며 오래된 메타 표본이 제한으로 표시되었다. Compose·CI YAML 구조, 변경 문서의 로컬 링크, Python·JavaScript 문법과 Git 공백 오류도 확인했다. Python의 물리 CPU 코어 수 확인 경고 1개는 논리 코어로 대체되어 테스트에 실패를 일으키지 않았다.

실제 Chrome 데스크톱에서 보관함의 백업·검색·복원 진입점을 확인하고 파일 선택 → 추가 1개 미리보기 → 명시적 적용 → 보관함 1개 반영을 확인했다. 자동 Playwright는 이 환경의 사용자 경로 접근 권한 때문에 실행하지 못했다. 모바일 렌더링과 전체 브라우저 회귀 검사는 추가한 CI 검사로 후속 확인해야 한다. Docker 실행 도구가 없어 실제 이미지·볼륨 동작도 로컬에서는 미검증이다. Ruff·Mypy·커버리지 도구는 현재 환경에 없고 네트워크 제한으로 추가 설치하지 못했으므로 해당 검사의 통과를 주장하지 않는다. 설치 dry-run은 수정된 프로젝트 경로까지 확인했으나 로컬 `wheel` 부재로 메타데이터 생성이 중단되었다. 새 환경의 전체 의존성 설치는 CI에서 확인해야 한다.

## 남은 작업

1. 전체 브라우저·Docker·정적 검사 CI 결과 확인. 이번 작업에서는 커밋·푸시·배포를 수행하지 않았다.
2. 행동 노트·초안까지 포함한 백업과, 필요 시 IndexedDB를 통한 다중 탭 트랜잭션 설계.
3. 동기화 API를 화면에 연결하려면 인증·소유권·충돌·실패 복구 방식을 먼저 확정. 현재 `client_id`는 인증 수단이 아니다.
4. 메타 자료는 10월 초 KR 16.19의 282경기 표본을 유지한다. 자동 주기 수집과 갱신 실패 기록은 후속 범위다.
5. AI 상태는 설정 확인과 실제 추론 성공을 구분해야 한다. 추론 서버 상태 확인과 실제 경기의 코칭 유용성 평가는 후속 범위다.

Redis 공유 요청 예산·캐시, 병렬 경기 조회, DuckDB/Parquet 어댑터와 SQLite 동기화 API는 기존 10월 후반 코드다. 이번 변경을 통해 새로 구현한 기능으로 소개하지 않는다.
