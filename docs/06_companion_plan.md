# LoL 인사이트 노트 — 서비스·분석 기획

기준일: 2026-10-04. 기존 SQL·통계 분석을 **자신의 랭크를 진지하게 복기하는 플레이어**를 위한 웹서비스로 확장한다. 이번 범위는 실행 가능한 로컬 뼈대, 브라우저 개인 기록과 기술 통계 비교, 공식 API 연결 코드까지다. 실제 키를 통한 전적 검증, 타임라인 분석, 개인별 비교 모델, LLM 연결과 배포는 후속 범위다. [상용 서비스 참고와 반영](07_service_benchmark.md) · [API 방식 검토](08_riot_integration.md)

## 서비스의 질문

“이 수치를 어떤 표본에서 얻었고, 내 상황에 어디까지 적용할 수 있으며, 다음 경기에서는 무엇을 확인하면 좋을까?”

관측 → 해석 범위 → 확인할 행동을 연결한다. 챔피언 순위와 승률을 늘리는 것만으로 차별화되었다고 주장하지 않는다.

## 차별화 가설과 첫 버전 반영

| 가설 | 첫 버전 구현 | 후속 검증 |
| --- | --- | --- |
| 근거와 표본 조건을 함께 보이면 수치의 적용 범위를 판단하기 쉬움 | 답변에 출처·지역·패치·티어·관측 단위와 해석 한계 표시 | 같은 질문에 수치만 보인 화면과 비교 조건을 보인 화면을 비교해 이해도 측정 |
| 최신 정보와 과거 통계를 구분하면 근거 없는 추천을 줄일 수 있음 | 공식 정적 자료 16.19.1, 공식 패치 노트 26.19, 과거 경기 15.1·15.3을 분리. 최신 승률·빌드 요청은 자료 부족으로 응답 | 근거 없는 최신 추천 비율과 답변 출처 정확성 평가 |
| 한 경기에서 검토할 행동을 직접 정하는 흐름이 복기에 도움이 될 수 있음 | 수동 경기 요약 → 복기 질문 → 브라우저에 행동 기록 | 과제 작성·완료율과 사용성 조사. 승률 변화는 탐색 지표로 두고 인과 개선으로 주장하지 않음 |

“연습 과제” 자체를 고유한 발명으로 내세우지 않는다. **근거를 열람하고 적용 가능성을 판단하는 복기 흐름**이 이 프로젝트의 집중 방향이며, 실제 차별성은 사용자 검증이 필요하다.

## 지금 실행 가능한 범위

- 인사이트 보드: 개인 기록과 같은 조건의 최근 3/직전 3경기 비교. 기존 메타·행동 집계는 별도 참고 자료.
- 챔피언 탐색: 공식 한국어 이름·분류·기본 수치와 과거 역할·패치 집계. 30행 미만의 승률 설명은 보류한다. 30행은 표시 기준이며 통계적 정밀도를 보장하지 않는다.
- 경기 복기: 수동 입력 또는 명시된 합성 예제의 GPM·DPM·시야/분·KP 계산. 팀 킬이 0이면 KP는 미정의다. 개인 실력·동티어 백분위는 계산하지 않는다.
- 분석 도우미: 등록된 집계·설명의 질문 탐색과 출처 제시. 현재 구현은 키워드와 응답 템플릿이며 LLM 추론이나 자율 에이전트가 아니다.
- 복기 기록: 브라우저에 경기 일시 기준 최근 50개 개인 요약·장면·행동 보관. 동일 조건·일시는 갱신하고 합성 예제는 제외한다. 자유 노트 10개는 별도 보존한다. 장면·행동은 서버·GitHub에 전송하지 않는다. 요약 수치와 조회 ID는 로컬 서버의 계산·공식 조회에만 전달된다.
- 공식 연결: KR 솔로듀오 최근 전적과 현재 랭크 조회 코드. 현재 랭크를 과거 경기 당시 티어로 넣지 않는다. 모의 응답 검증이며 실제 키 조회는 미완료다.

서비스는 원본 DB나 `player_segments.csv`를 읽지 않고, 기존 집계 CSV와 공식 정적 자료만 읽는다. 과거 CSV의 `n_games`는 군집별 **경기×참여자 행 수**이며 고유 경기 수로 바꾸어 표시하지 않는다. 챔피언 CSV의 픽 비중 분모도 역할별 표본이 아니라 전체 코호트 참여 행이다.

## 후속 분석 설계

### 1. 표본 구성을 맞춘 패치 비교

질문: 같은 티어·역할 구성으로 비교해도 챔피언 변화가 유지되는가?

- 최신 KR 솔로듀오의 인접 패치 경기 표본을 새로 수집한다. 기존 EUN 15.1·15.3과 최신 KR을 한 비교 집단으로 섞지 않는다.
- 관측 기간·큐·지역·티어·역할·표본 수·누락 비율을 데이터 사전에 고정한다. 같은 경기에서 반복되는 참여 행의 의존성과 중복을 검사한다.
- 원래 전체 비교, 공통 티어 제한, 티어×역할 기준 표준화 결과를 나란히 본다. 중첩되지 않는 조건은 외삽하지 않는다.
- 경기 단위 재표집 신뢰구간, 최소 효과 크기와 다중 비교 보정을 추가한다. 효과 크기·불확실성·표본 가용성을 함께 제시한다.
- 관찰 분석이므로 패치의 인과효과나 다음 패치의 사전 예측으로 주장하지 않는다. 예측을 평가하려면 분석 시점·정보 컷오프와 미래 평가를 따로 고정한다.

### 2. 상황을 맞춘 개인 복기

질문: 같은 패치·역할·실력대·경기 길이에서 내 행동의 어떤 부분을 다시 확인할 수 있는가?

- 사용자가 조회한 완료 경기만 연결하고 PUUID는 서버 내부의 식별자로 관리한다. 공개 파일과 로그에서 식별자를 제외한다.
- 기본 비교 단위는 경기×참여자다. 반복 관측이 확보되기 전에는 개인의 고정 성향·이탈 위험을 추정하지 않는다.
- 시야 점수는 경기 길이에 민감하므로 시야/분을 함께 본다. GPM·DPM·KP도 승패와 흐름의 영향이 남아 있어 결과 신호를 제거했다고 주장하지 않는다.
- 게임 타임라인으로 오브젝트 전 준비·회귀 시점 등 실제 행동을 확인할 수 있는지 먼저 감사한다. 데이터가 부족하면 “확인 필요”로 반환한다.
- 충분한 비교 표본과 불확실성을 확보한 뒤 상대 위치를 제시한다. 공식 랭크를 대체하는 MMR·ELO 점수는 만들지 않는다.

### 3. 근거를 갖춘 대화형 도우미

- 질문 분류 → 허용된 분석 도구 실행 → 구조화된 근거 반환 → 설명 생성 순서를 유지한다.
- 근거마다 버전·기간·지역·표본·계산 단위·산출물 링크를 붙인다. 원본 문서의 지시나 외부 텍스트가 실행 권한을 바꾸지 않도록 한다.
- LLM은 이후 서버 측에서 선택적으로 연결한다. 키·개인 식별자·원본 경기 행을 브라우저 코드나 공개 로그에 넣지 않는다.
- 최신성 요청, 표본 부족, 없는 챔피언, 조건 불일치, 분모 0, 범위 밖 질문의 답변을 평가 사례로 고정한다.
- 답변 품질 지표는 근거 정확성·수치 일치·적절한 보류·행동 가능성이다. 문장이 자연스럽다는 이유만으로 정답으로 처리하지 않는다.

## 정책과 데이터 연결 조건

[Riot 일반 정책](https://developer.riotgames.com/policies/general)과 [LoL 개발자 문서](https://developer.riotgames.com/docs/lol)는 플레이어 대상 서비스 등록, 키 보안, 비공식 서비스 고지와 공정성을 요구한다. 실제 이용자에게 배포할 때 Developer Portal 등록·승인 범위를 확인한다. 현재는 로컬 개발 뼈대이며 승인된 운영 서비스라고 소개하지 않는다.

숨겨진 플레이어 식별, 게임 자동 조작, 공식 랭크 대체, 비공개 인게임 정보 활용은 구현 범위에 포함하지 않는다. 이번 방향은 완료 경기의 검토다. 기존 데스크톱 서비스의 기능을 이유로 같은 기능이 자동 허용된다고 해석하지 않는다.

Data Dragon 버전은 지역 클라이언트 버전과 항상 같지 않을 수 있어 KR realm을 함께 확인한다. 정적 자료와 패치 노트의 버전은 같은 숫자 체계를 쓰지 않는다. 원본 Kaggle 데이터셋의 정확한 출처·이용 조건도 새 재배포나 학습 범위 확장 전에 확인한다.

## 돌아온 뒤 정할 사항

1. 주 사용자와 우선순위는 본인 중심의 개인 랭크 복기로 정했다. 실제 사용에서 어떤 장면과 행동을 기록하기 쉬운지 확인한다.
2. 유효한 로컬 키로 공식 전적을 조회하고 경기 수치·포지션·현재 랭크·누락 경기를 대조한다.
3. Riot Developer Portal 등록과 서버 측 키, 사용자 조회·보관 범위.
4. LLM 제공자와 비용 한도, 답변 평가 사례.
5. 최신 KR 표본의 수집 계획과 비교 설계 확정 후 실제 분석 실행.

현재 화면은 로컬 첫 버전이다. 이 문서의 후속 분석·최신 개인화·승률 개선 검증이 완료되었다고 표시하지 않는다.
